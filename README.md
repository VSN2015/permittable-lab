# permittable-lab

A set of Rails apps that exercise the [`permittable`](https://rubygems.org/gems/permittable) gem against its
README on Rails 7.2, 8.0 and 8.1, in Docker. The README of the gem is the source of truth: each spec
claims one README behaviour, and `docs/coverage-matrix.yml` tracks which README claims are covered.
The three apps (`apps/rails-7_2`, `apps/rails-8_0`, `apps/rails-8_1`) are generated by `rails new`,
patched by `shared/bin/patch_app.rb`, and run the same code and specs from `shared/`.

## Usage

    docker compose up                 # all three apps and PostgreSQL
    bin/test [7.2|8.0|8.1] [rspec args]   # default 8.1, e.g. bin/test 7.2 shared/spec/requests
    bin/matrix                        # 7.2, 8.0, 8.1; logs in tmp/matrix/VERSION.log; exit 0 only if all PASS
    bin/coverage-report [--strict]    # README coverage per matrix row, remaining rows per plan
    bin/new-app <7.2|8.0|8.1>         # generate an app (run `docker compose build` first)
    ruby shared/bin/patch_app.rb apps/rails-X_Y   # idempotent; run after bin/new-app

## Environment variables

| Variable | Meaning |
|---|---|
| `PERMITTABLE_PATH` | Host checkout of the gem, mounted read-only at `/permittable`. Default `~/Projects/individual-projects/permittable`. |
| `PERMITTABLE_SOURCE` | `local` (default, the mounted checkout) or `rubygems`. |
| `PERMITTABLE_VERSION` | Exact gem version to install when the source is `rubygems`, e.g. `0.13.1`. Specs tagged `since:` newer than it are listed as not applicable, never silently skipped. |

    PERMITTABLE_SOURCE=rubygems PERMITTABLE_VERSION=0.13.1 bin/matrix

## Adding a spec

1. Pick a row in `docs/coverage-matrix.yml` and put `covers: "row-id"` in the example metadata
   (one row per claim; a row may have several examples).
2. Put a `# README:` comment above the example quoting or pointing to the README line it checks.
3. Use `since: "x.y.z"` only when the behaviour arrived in that gem version. It is about gem versions
   only, never Rails versions.
4. Flip the row's status in the matrix to covered and run `bin/coverage-report --strict`.

## Anti-goals

- No expectation is ever bent to match what the gem does. The README decides.
- No version guard that hides a red case on a Rails version.
- No edits to `rails new` default files beyond `bin/new-app`'s `database.yml` edit and
  what `patch_app.rb` adds (Gemfile `eval_gemfile`, `.rspec`, the `Lab::Boot` hook).
- No per-version forks of shared code.

## Per-version notes

Plan 1 ran the same 189 specs on 7.2.4, 8.0.5.2 and 8.1.4.1. The only lab change needed for 7.2 and 8.0:

- **json gem**: Rails 8.0's ActiveSupport JSON encoder passes `quirks_mode:` to `JSON.generate`, which
  json 3.x rejects (`unknown keyword: quirks_mode`, hit when a migration defines a column default).
  `shared/gemfile.rb` pins `gem "json", "< 3.0"` for all three apps.

Checked and needing no change:

- `rails new` flags: `--skip-kamal` and `--skip-thruster` do not exist in 7.2; `bin/new-app` drops them.
- `config.load_defaults` follows each app's own version (7.2, 8.0, 8.1); the shared code does not depend on it.
- `show_exceptions`: generated `test.rb` uses `:rescuable` on all three.
- `allow_browser versions: :modern` is in the generated `ApplicationController` of all three; lab controllers do not inherit from it.
- Inspector `LogTap` and `ActiveSupport::BroadcastLogger` work on all three (BroadcastLogger exists since 7.1).
- `Hash#inspect` spacing, Zeitwerk `autoload_once_paths` and Cuprite behave the same on all three for the covered specs.

## Findings policy

A spec that is red on one Rails version because of a lab or version incompatibility is a lab bug and is
fixed once in `shared/`. A spec that is red because the gem behaves differently from its README is a
**finding**: it stays red, is recorded in the hand-off with the Rails version, the README line, the
observed behaviour and a minimal repro, and is never fixed by editing the expectation.

## Findings (gem vs README)

None so far (Plan 1: 189 examples, 0 failures on Rails 7.2, 8.0, 8.1).
